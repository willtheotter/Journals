Week 5 — October 3, 2026

QuickSort, Tree Traversals & Decrease-and-Conquer

This week's module introduced QuickSort, a divide-and-conquer sorting algorithm that partitions the array around a pivot and recursively sorts the subarrays. I learned that QuickSort has an average time complexity of O(n log n) but a worst-case of O(n²) when the pivot is poorly chosen (e.g., already sorted input with first-element pivot). The median-of-three partitioning strategy helps mitigate this. We also covered binary tree traversals (preorder, inorder, postorder) and how to calculate the height of a binary tree. The decrease-and-conquer paradigm was introduced with binary search and topological sorting using Kahn's algorithm for DAGs. Finally, we explored transform-and-conquer with pre-sorting as a problem-solving strategy.

Key learnings:

  • QuickSort: Partition around pivot → recursively sort subarrays. Average: O(n log n), Worst: O(n²). In-place but not stable.
  • Median-of-Three: Choosing the median of first, middle, and last elements as pivot improves partitioning balance.
  • Binary Tree Traversals: Preorder (root-left-right), Inorder (left-root-right), Postorder (left-right-root). Height = max depth of tree.
  • Decrease-and-Conquer: Binary search reduces problem size by half each step → O(log n). Requires sorted input.
  • Topological Sorting: Kahn's algorithm uses in-degree counts and a queue to order DAG vertices. Time: O(V+E).
  • Transform-and-Conquer: Pre-sorting simplifies problems (e.g., finding closest pair, checking duplicates) by enabling efficient comparisons.
  • Puzzles: Solved the FamousActor puzzle (graph connectivity) and King's Reach puzzle (pre-sorting strategy).

Topics: QuickSort · Median-of-Three · Tree Traversals · Binary Search · Topological Sorting · Kahn's Algorithm · Pre-sorting

Week 4 — September 28, 2026

MergeSort & Midterm Review

This week focused on MergeSort, a divide-and-conquer sorting algorithm, and midterm preparation. MergeSort recursively divides the array into halves, sorts each half, and then merges them back together in sorted order. I learned that its time efficiency is O(n log n) in all cases (best, average, and worst), which makes it more consistent than QuickSort. The space complexity is O(n) due to the auxiliary arrays used during merging. I also reviewed key topics for the midterm, including asymptotic notations, recurrence relations, brute force algorithms, DFS/BFS, and the Master Theorem. The midterm review session with the TA helped clarify the divide-and-conquer analysis.

Key learnings:

  • MergeSort: Divide array in half → recursively sort each half → merge sorted halves. Stable sort with O(n log n) time complexity in all cases.
  • Recurrence Relation: T(n) = 2T(n/2) + O(n) → solved using Master Theorem (Case 2) → O(n log n).
  • Space Complexity: O(n) auxiliary space for merging, unlike in-place sorts like QuickSort.
  • Midterm Review: Covered asymptotic notations (Big O, Omega, Theta), nonrecursive/recursive analysis, DFS/BFS, brute force, and divide-and-conquer.
  • Reference Sheet: Prepared a two-page reference sheet summarizing key formulas, recurrence relations, and algorithm efficiencies.

Topics: MergeSort · Divide and Conquer · O(n log n) · Midterm Review · Recurrence Relations

Week 3 — September 21, 2026

Brute Force, Graph Traversal & Divide and Conquer

This week's module expanded on brute force techniques with string matching and exhaustive search problems like TSP, Knapsack, and the Assignment problem. I learned how brute force guarantees a solution but often at exponential cost. The module then introduced graph traversal algorithms—Depth-First Search (DFS) and Breadth-First Search (BFS)—including their time efficiencies (both O(V+E) for adjacency lists). Finally, we began exploring the divide-and-conquer design paradigm and the Master Theorem for analyzing recurrence relations of divide-and-conquer algorithms.

Key learnings:

  • Brute Force String Matching: O(nm) worst-case — compares pattern against every position in text.
  • Exhaustive Search: TSP (n! permutations), Knapsack (2ⁿ subsets), Assignment (n! permutations) — all factorial or exponential.
  • DFS: Uses a stack (or recursion), explores as deep as possible before backtracking. Time: O(V+E) with adjacency list.
  • BFS: Uses a queue, explores level by level. Finds shortest path in unweighted graphs. Time: O(V+E).
  • Divide and Conquer: Divides problem into subproblems, solves recursively, combines results. Master Theorem: T(n) = aT(n/b) + f(n).
  • Puzzles: Solved the FakeCoin puzzle (dividing coins into groups) and the Finger Count puzzle (pattern recognition).

Topics: Brute Force · String Matching · TSP · DFS · BFS · Divide and Conquer · Master Theorem

Week 2 — September 14, 2026

Asymptotic Notations & Algorithm Analysis

This week's module focused on asymptotic notations (Big O, Big Omega, Big Theta) and their role in analyzing algorithm efficiency. I learned the formal definitions and practiced applying them to both nonrecursive and recursive algorithms. The OpenStax figures helped me visualize orders of growth, making it clearer why O(n²) grows so much faster than O(n log n). I also studied recurrence relations and backward substitution for analyzing recursive algorithms like the Tower of Hanoi. The brute force algorithm design lecture introduced a straightforward problem-solving approach that serves as a baseline for comparison with more sophisticated techniques.

Key learnings:

  • Asymptotic Notations: Big O (upper bound), Big Omega (lower bound), and Big Theta (tight bound). Formal definitions using constants c and n₀.
  • Nonrecursive Analysis: Counting basic operations and identifying loop-dependent growth rates. Example: nested loops → O(n²).
  • Recursive Analysis: Setting up recurrence relations and solving via backward substitution. Tower of Hanoi: T(n) = 2T(n-1) + 1 → O(2ⁿ).
  • Brute Force: Straightforward approach that guarantees a solution but may lack efficiency. Useful as a baseline for optimization.
  • Puzzles: Solved the 4-gallons water puzzle and the racing cars puzzle, reinforcing logical step-by-step problem-solving.

Topics: Big O · Big Omega · Big Theta · Recurrence Relations · Tower of Hanoi · Brute Force

Week 1 — September 5, 2026

Introduction to Algorithms & Pseudocode

This week's module covered foundational concepts including algorithm definitions, Euclid's algorithm for GCD calculation, pseudocode notation, and important problem types such as sorting, searching, and graph problems. We also reviewed fundamental data structures (arrays, linked lists, trees, graphs) and began exploring the algorithm analysis framework.

Key learnings:

  • Euclid's Algorithm: gcd(m,n) = gcd(n, m mod n). Example: gcd(6,10) = gcd(6,4) = gcd(4,2) = gcd(2,0) = 2.
  • Pseudocode: Practiced identifying basic operations like comparisons (<) and arithmetic (+) within loops.
  • Graph Representations: Reviewed adjacency matrices and adjacency lists for weighted vs. unweighted graphs.
  • Puzzles: Solved the fake coin puzzle (9 coins, 2 weighings) and the choosing balls in the dark puzzle (best case: 2, worst case: 13).

Topics: Algorithms · Euclid's GCD · Pseudocode · Graphs · Problem Types
